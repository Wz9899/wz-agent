# 两阶段 Prompt 切换

需求澄清（追问用户）和编码执行（写代码）使用两套独立系统 prompt，通过显式状态切换完成衔接。单一 prompt 同时管两件事会导致状态混淆：LLM 可能在编码中段突然开始追问，或在追问阶段就开始写代码。

## 考虑过的替代方案

**单一 prompt 管全部。** 在系统 prompt 中同时写入追问规则和编码规则，让 LLM 自己判断何时切换。被拒绝——状态边界模糊，LLM 容易在错误时机做错误的事。

## 影响

- 需要维护两套 prompt 模板
- 阶段切换需要明确的状态机（由应用层控制，不依赖 LLM 自觉）
- 未来如需支持"编码中段再次追问"的场景，可在阶段二 prompt 中按需嵌入轻量追问权
